## Git 操作
- コミット・タグ作成・プッシュは、その依頼の中で明示的に指示された場合のみ行う。

## 質問と修正の切り分け
- 質問(「〜できるか」「〜はどうなっているか」「〜とは」)には、まず回答する。
  コードの修正には着手しない。修正は「修正して」「実装して」と明示されてから行う。
- 仕様や意図に不明点がある場合は、修正に取りかからずに先に問い合わせる。
  推測で進めない。

## アクセス範囲
- リポジトリの外にあるファイルの読み書きは、事前に許可を得る。
 許可はセッション中に1回で良い。
- 外部データへのアクセス(Web、API、他リポジトリ、ネットワーク上のリソース)は、事前に許可を得る。
 許可はセッション中に1回で良い。

## ビルドとリリース
- `cargo test` は PowerShell から実行する(Git Bash 経由では ConPTY テストがハングする)。
- スクリプトの動作確認以外で、パッケージ作成は行わないこと
- バージョン変更で更新するファイルの一覧は `docs/version-update-checklist.md` を作成しておく。

## 推測と情報の扱いに関するルール
1. **断定の禁止**: 
   - 確実な根拠（提供されたデータやドキュメント）がない事項について、事実として断定してはいけません。
2. **推測の明示**: 
   - やむを得ず推測や仮説を述べる場合は、文頭または文末に「※推測です」「〜と推測されます」といった表現を必ず明示してください。
   - 推測で解決しなかった場合はそれ以上推測を重ねず、ログ取得によって原因を特定してください。
3. **確認の優先**: 
   - ユーザーの指示や情報が曖昧で、重大な判断・実装ミスにつながる恐れがある場合は、推測で補完せず、まずユーザーに追加の質問を行ってください。
4. **禁止事項（悪い例）**:
   - 根拠のない独自の仕様や外部ライブラリの挙動を、確認なしに存在するものとしてコードに組み込むことを禁止します。
   - コードのライセンスに常に留意してください。
